# Security review — 0.5.22

Reviewed 2026-10-15. The optional inspector is Node's built-in HTTP server with vanilla browser JavaScript; no Express framework is used. JavaScript security guidance was applied to that surface. BrightScript/native SceneGraph paths were reviewed separately. This is a repository-grounded review with deterministic tests, not a penetration test or hardware certificate.

## Findings and resolutions

| ID / severity | Evidence / impact | Resolution / verification |
|---|---|---|
| SEC-1 / medium — LAN authorization | `source/util/SetupPage.brs` routes imports to the Scene. Host/Origin checks block browser cross-site/rebinding requests but do not authenticate a native LAN client that forges headers. Previously an open Add-ons screen was the only user gate. | `components/SetupImport.brs:4` queues a TV confirmation; default is Cancel, expiry is 60 seconds. `onSetupImportChoice` at line 22 checks generation/expiry and calls the existing open-screen import gate. `ExpireSetupImport` at line 39 clears abandoned/private request state. Production tests cover closed screen, repeated request, no installation before consent, cancellation, expiry and stale account. Existing private bind, eight-connection/64 KiB request budgets, idle/absolute deadlines and forbidden playback mutation remain. |
| SEC-2 / medium — untrusted diagnostic reflection | `components/MainScene.brs:823` previously appended raw account API error text to the fault strip; worker exceptions may contain private request details. No actual exposure was demonstrated. | Sync UI now uses fixed messages plus numeric outcome counts. `AddonSyncTask` catches exceptions with a fixed error. Private provider paths/queries stay in internal state and are never included in sync status. |
| SEC-3 / low — CSP hardening (JS-CSP-001/002) | Optional inspector handled private inputs without a CSP. DOM output already used textContent/createElement, with no demonstrated executable sink. | `scripts/preflight-server.js:10` hashes the exact trusted inline script and sends a restrictive header policy at line 30. No unsafe-eval or broad script allowlist. Existing same-origin runtime key, Host checks, loopback binding, no-store/no-referrer and redacted failures remain. HTTP test checks the served script digest and cross-origin refusal. Input/header deadlines bound slow uploads; the input socket timeout is cleared before bounded media inspection. |
| SEC-4 / low — Roku form response headers | The static LAN setup form did not send CSP or clickjacking/referrer restrictions. It executes no JavaScript and reflects no configured URL into HTML. | `source/util/SetupPage.brs:444` now emits default-src none, form-action self, frame-ancestors none, base-uri none, no-referrer, nosniff and no-store. Inline styles are deliberately permitted for this static form. |
| SEC-5 / development-tool maintenance | Fresh `npm audit --json` reports 9 affected development dependency entries, representing 2 underlying advisories: 7 high, 2 moderate, 0 critical. These are not installed Roku dependencies. | Documented in DEVELOPMENT.md. No incompatible override/downgrade is used to hide the result. Keep build globs/source maps trusted and validate an upstream/toolchain replacement separately. |

There is no confirmed unresolved critical/high finding in the reviewed application paths. This statement is limited to the inspected code and tests. It does not negate the reported development-tool advisories or certify every third-party provider.

## Boundaries and evidence

- Public provider configuration still requires HTTPS. Explicit local-development HTTP accepts only permitted private addresses; it cannot admit public HTTP. Existing tests cover scheme admission and exact path/query preservation.
- Account keys, configured provider URLs, signed media URLs and account caches are private state. The package contains no configured service account or paid access. Secret-pattern/content review covers working files, reachable history and ZIP contents; reviewed synthetic fixtures are classified separately. Pattern scans do not validate credentials.
- Browser inputs are password-style fields with autocomplete disabled; reports use safe text insertion and contain no configured URLs/headers. No remote scripts, eval, document.write or localStorage credential persistence were found in the inspector page. CSP is defense in depth; no exploitable DOM XSS was claimed.
- The Roku setup listener is HTTP on a private interface and the optional inspector is HTTP on loopback. TV confirmation prevents unattended import but does not encrypt LAN traffic or authenticate a legitimate provider. Use the one-time setup form on a trusted local network. This is an architectural limitation, not an internet-facing TLS finding.
- Read-only public schema research and local mocks were used. No private account, remote account destruction, subscription purchase, credential validation, live Roku setting change or native playback was performed.
