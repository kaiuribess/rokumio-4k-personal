# Development and contributions

## Build and validate

Use Node.js 22 LTS, npm and Python 3.12+ for the package verifier. The lockfile records development dependencies. On a clean checkout:

```sh
npm ci --ignore-scripts
npm test
npm run build
python scripts/verify-package.py
```

`npm test` transpiles stores and executes production BrightScript callbacks in the `@rokucommunity/brs` interpreter, plus Node media/transport suites and a local mock add-on. Native SceneGraph/device boundaries are simulated. Tests do not certify acoustic sound, actual Roku OS scheduling, HDMI/HDR negotiation or entire films.

The verifier checks ZIP integrity, manifest fields, component inheritance, every packaged XML script reference and exclusion of development files. The compiled archive has `manifest` at its root. Build output is excluded from Git; downloadable ZIPs belong to Releases.

## Architecture

- `source/main.brs`: Roku screen, input events and local setup socket loop.
- `components/MainScene.brs`: navigation, shared StoreHost binding and deferred account writes.
- `source/core/ScreenStack.bs`: static screen lifetime, focus and Back routing.
- `components/StoreHost.brs`: stores remain inside one component; plain data and SG-node references cross component boundaries.
- `StreamsScreen`: provider loading, source cards, fresh-link refresh, quality filter and automatic selection.
- `StreamResolveTask` / media utilities: resolution and bounded preflight work away from the render thread.
- `PlayerScreen`: native Video handoff, buffering deadline, watch-state persistence, subtitles and playback facts.
- `PlayerAudioRecovery` / `EnglishAudio` / `AudioCapabilities`: bounded English track recovery and native compatibility observations.
- `PlayerSourceMemory` / `SourceMemory`: hashed identities of working sources; private signed URLs are not persisted as cache identities.
- `SourcePrefetch`: short-lived source-list preloading tied to provider/audio context.
- `SourcePrefetchCoordinator`: sole production owner of warm and explicit source-list workers, shared two-slot budget, abandoned-transfer ownership and suspended queues. StreamsScreen adopts its results instead of launching another provider batch.
- `NextEpisode` / `PlayerNextEpisode`: provider-id-preserving episode order, future-date gate and cancellable timer transition.
- `AddonDiagnostics` / `AddonHealthTask` / `AddonHealthScreen`: sequential manifest reachability checks, sanitized categories, progressive status and cancellation. Source-provider failures also appear in `StreamsScreen`; successful manifests do not certify account entitlement or playback.
- `AudioSetup` / `SettingsAudio`: explicit equipment selection, wiring instructions and fresh native capability reports. They do not change system settings or transcode audio.
- `Theme.bs` / Crimson image assets / `AboutScreen`: shared red palette, branding and small upstream credit. Internal registry keys, DIAL title and deep-link prefixes remain compatible with existing installations.
- `HomeCatalogPolicy` / `HomeCatalogsTask` / `HomeCinema`: bounded samples, sequential catalog loading, compact/expanded native RowList layout, shortcuts, debounced featured artwork and hidden-screen UI deferral. Discover retains full provider browsing.
- `PlaybackPreferences` / `SettingsStore`: typed, persistent quality/autoplay/recovery preferences with current-playback overrides.
- `ProviderPriority` / `SettingsProvider`: opaque public-ID/hostname fingerprints, stable waiting-order preference and native scrolling source selection. Last-working provider is recorded at the existing sustained native A/V/English proof gate, excluding diagnostics.
- `TimerGuard` / `PlayerPosition`: monotonic current-operation delays and source-scoped last position/duration observations for safe recovery after native terminal resets.

The original geometric Crimson icon is generated by `scripts/generate-crimson-brand.py`. Re-exporting PNG assets requires Python and Pillow; those tools are not required for the normal app build. The generator uses existing bundled Open Sans fonts.

## Next-episode implementation

Details and episode selection carry complete series metadata where available. The player fetches missing metadata through a deferred `MetaLoaderTask`. Only an accepted native `finished` state schedules the countdown; a measured early ending stays in same-episode recovery. Diagnostic samples and movies do not advance.

The finish observer only starts a pre-existing Timer. The timer saves completion, emits a current-video-scoped request, and MainScene removes the old player and reuses the existing StreamsScreen. This avoids duplicate references to static screens and unbounded navigation growth. Fresh source candidates are fetched for the new provider episode id, with position zero and the same quality/audio preferences.

Keep SG node creation, teardown and navigation outside native Video transition callbacks. Previous versions encountered device freezes when worker creation ran on that observer stack; an interpreter pass is not enough to validate this scheduling boundary.

## Stick resource policy

Home stores at most 12 catalog preview rows of 24 whitelisted metadata records. Each row carries its provider/catalog/type/genre so See all preserves access to the full feed. Long provider synopses remain in Details; Home uses a separate 280-character overview. Preserve declared square/landscape poster shape when sampling.

One sequential Task makes up to eight base-catalog requests, eight genre requests and eight missing-manifest requests; only advertised genre options are used. Individual failures skip a row. Results arriving while Home is hidden update bounded data but do not create poster nodes. The featured image is 640×274, loads asynchronously, changes only after a 250 ms stable-focus delay, and is cleared on blur/expanded browse. No video preview, movie URL probe or metadata request occurs on poster focus.

Native image sizes and off-thread requests follow Roku's [Poster](https://developer.roku.com/dev/docs/poster) and [threading](https://developer.roku.com/dev/docs/threads) guidance. Static [Timer](https://developer.roku.com/dev/docs/timer) callbacks are checked against a freshly marked [roTimespan](https://developer.roku.com/dev/docs/rotimespan), because stopping/restarting a timer does not make an already queued event belong to the new operation. Re-arm the remaining delay rather than execute the new action early. Existing active/generation/cancellation guards remain necessary.

SourcePrefetch retains one title for 60 seconds, at most four providers and 256 unique candidates per provider, reserving up to 64 labelled UHD candidates. SourceMemory persists only 32 hashed outcomes with expiry. Player exit clears the old queue and handoff metadata after saving resume state. Do not replace these caps with full provider arrays or remove full browsing to optimize the preview.

Warm preload and explicit lookup share at most two owned source-list workers. Explicit loading queues every matching provider; ordinary provider responses remain available without a new source-count cap. A canceled title loses its queued work and UI ownership, but already-running workers remain observed by the coordinator until their result releases the slot. Never free a live slot just because its screen was removed or STOP was sent. Tokens keep that result out of a later title. The transport has bounded request waits; this is not proof of a hard socket/response-byte or sustained-media limit.

Automatic Play defaults to Start sooner. A guarded 750 ms interval from ready candidates allows brief comparison, then ranks the currently available pool on a Task without waiting for every provider. Complete responses may start immediately; 4K-only waits for eligible UHD hints. An empty early selection can be reconsidered after the source revision changes. Compare providers preserves the all-response behavior as a saved boolean preference. Manual selection, cancellation and quality changes disown stale selection workers/timers. The initial retry pool may be smaller with early selection; pending results remain for return to the picker and are never injected into accepted playback.

Provider priority changes delivery order, not source URL validity. Keep priority out of the source cache key; SetPriority updates queued order without pumping, clearing completed data or preempting active transfers. Prefer the explicit key, then last-working key, then stable original indices. Warm preload chooses at most four attempted providers across the full installed set; aligned idle slots preserve index mapping when explicit Play adopts every provider. Key storage contains only two validated SHA-256 strings. Do not persist configured manifest paths, queries or userinfo as preferences.

Manual paging keeps at most 48 real source cards plus two fixed navigation rows. Map each visible source to its full retained-array index, token, provider and page. Navigation rows keep fixed indices across page/filter/provider changes once paging is enabled so an old More/Previous selection cannot become a movie. Cancel automatic ranking on manual browsing; preserve page/focus on unrelated late results and Player return. The player's retry pool remains the full retained list. This does not remove the existing warm-cache 256 cap or bound ordinary response bytes.

The Preferred source section uses a fresh native RowList with the same layout/style, uniquely numbered sender id, removed old observer/node and an event sender guard. This prevents stale main/subsection selections from applying a different action. Recent preference persistence happens after the existing 10-second sampled native progress proof, outside Video state observer callbacks; duplicate successful records avoid writes and refused writes retain a retry flag.

No Roku frame-rate, texture-memory or sustained-decoder profiling was performed for 0.5.16. Use physical-device resource measurements before making performance claims. Computer tests verify bounds, callback ownership and cleanup, rather than real rendering speed.

## Audit regression repairs in 0.5.17

Complete flow tests supplement the isolated screen tests. `catalog-integration` uses the compiled CatalogStore, actual DiscoverLoaderTask and current Discover callbacks, starting with a previously loaded catalog. Raw consumed records cross both boundaries independently of usable tiles. `library-origin` follows Details save, actual LibraryStore serialization, My list selection and episode request routing. It substitutes native/store-host/network boundaries and digest output. Older custom IDs favor compatible metadata providers with specific prefixes; Cinemeta restoration is limited to IMDb identifiers.

Accepted progress is saved on the recovery timer before decoder teardown through the existing store/watch-state path; replacement probes cannot overwrite it. Working-source proof rearms with fresh samples after resumed accepted playback. Tests exercise both combinations that earlier isolated callbacks missed. Native functions execute in their owning component through [callFunc](https://developer.roku.com/dev/docs/ifsgnodedict); StoreHost interface/type/count checks include the extended optional metadata-key arguments.

Warm results carry diagnostic counts alongside capped candidates. Public setup no longer dispatches diagnostic playback mutations; its normal import gate remains. Connection sweeps use monotonic elapsed time with 10-second idle and 30-second absolute deadlines, including stalled writes. They run every main-loop iteration without blocking sockets.

Legacy server settings do not alter source admission. Raw torrent/hash-only playback is unsupported in this build; the retained upstream resolver must not be advertised as an enabled public mode.

## Source inspector

`npm run check-source` runs an optional local PC diagnostic interface. It performs bounded metadata inspection and does not download a whole film or prove Roku decoding. The app does not depend on it during playback. Do not expose the inspector or Roku local setup/diagnostic ports to the internet. Avoid sharing configured manifests, signed URLs or keys in reports.

## Contributing / fork instructions

Fork the GitHub repo, create a branch, make a bounded change, run relevant production callback tests and the full build/package checks, then open a PR explaining the trigger and before/after behavior. Keep the MIT notice and font license in redistributions. Do not commit account configuration, browser profiles, installer passwords, device dumps or private playback logs.

For a playback issue, report the app version, Roku model/OS, container, video/audio codec, channel layout, declared language, connection route and safe error code. Redact all private URLs and provider identifiers. State whether resolution comes from a label, file metadata or native segment data. Physical-device test results should identify exactly what was observed without turning one working sample into a universal claim.

## Development dependency audit

On 2026-10-14, the locked development toolchain was updated from `@rokucommunity/brs` 0.47.4 to 0.47.6 and `brighterscript` 0.73.1 to 0.73.7, using `npm install --ignore-scripts`. The interpreter's [supported patch release](https://github.com/rokucommunity/brs/releases/tag/v0.47.6) removes the abandoned `decompress` dependency and updates `uuid` from 8.3.2 to 11.1.1. The dependency tree shrank from 267 to 208 packages. `npm audit` changed from 11 affected dependency entries (3 moderate, 7 high, 1 critical) to 9 (2 moderate, 7 high, 0 critical). These counts include packages affected transitively; they do not represent nine distinct underlying advisories.

Two underlying advisories remain: [deeply nested patterns in `braces` through 3.0.3](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm), for which no patched version is published, and [malformed input decoding in `decode-uri-component` through 0.4.2](https://github.com/advisories/GHSA-vcc3-ghjq-m6fr), reached in the dependency tree through `nanomatch` / `snapdragon` / `source-map-resolve`. The latter's patched 0.5.0 is ESM, while its existing caller uses CommonJS `require()`. Forcing that override would change the caller's API contract; no unsafe override or compiler downgrade is used to hide the findings. Replacing these upstream dependencies requires separately validated maintenance. Keep development globs and source-map inputs trusted and re-run `npm audit` for current details.

These Node development dependencies are not bundled in the Roku ZIP, so these findings are not equivalent vulnerabilities in the installed Roku app. They still matter to contributors who run the tools. Use `npm ci --ignore-scripts`; CI disables dependency lifecycle scripts too. The upgraded compiler/interpreter is checked with the production store harness and the release's full test/build/package validation. A passing app test does not establish that the toolchain is advisory-free.

## Reliability audit repairs in 0.5.18

See [Changes](../CHANGELOG.md) and [Validation](VALIDATION.md). The new failure-injection suites execute production stores, account orchestration, file acquisition, recovery and checkpoints with native I/O/task/registry doubles. They do not log in, send account changes, contact movie providers or access a Roku. Decoded oversize tests supply native file sizes; real HTTP content decoding and cancellation timing still need a device check.

CI runs the full suite, builds once, verifies that ZIP, and writes its SHA-256/commit/run provenance. `scripts/release-provenance.py` refuses a changed package after verification. The release process downloads the successful artifact for the exact commit, renames its install ZIP without changing its bytes, and uploads it alongside package-check.json, artifact-provenance.json and the SHA-256 file. Independently download the public asset and compare its full hash with the CI artifact. Do not rebuild between validation and publication.

Before stable status, perform clean install and upgrade, held-account-result isolation, a full movie, consecutive episodes, repeated seeking, Back during loading, expired/failed-source recovery and repeated-navigation memory measurements. Test audible stereo and the actual HDMI surround route separately. Passing software assertions cannot replace that sign-off.
